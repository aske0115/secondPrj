# 콘텐츠 추가 파이프라인 (설계 초안, 결정 012)

목표: **어떤 AI(Claude, ChatGPT, Codex 등)에게 맡겨도** 이 문서와 형식만 읽고 새 방·소품·고장 유형·이야기를 추가할 수 있게 한다. 사람은 미리보기 이미지를 보고 승인만 한다.

## 1. 원칙
- 콘텐츠는 **코드가 아니라 데이터 파일**입니다. 새 방을 넣으려고 게임 코드를 고치지 않습니다.
- AI가 틀리기 쉬운 부분은 **사람의 눈이 아니라 자동 검사**가 막습니다.
- 정성은 사람이 고르는 단계에서 들어갑니다. AI는 여러 안을 만들고, 사람은 고르고 다듬습니다.

## 2. 무엇을 데이터로 두는가

| 종류 | 파일(예정) | 내용 | 누가 만들기 쉬운가 |
|---|---|---|---|
| 소품 목록 | `content/props/*.json` | 소품 ID, 3D 모델 파일, 크기, 놓일 수 있는 자리 종류(선반·벽·바닥), 가능한 고장 유형, 한영 이름 | AI가 에셋 목록을 보고 작성 |
| 고장 유형 | `content/faults/*.json` | 먼지·금 감·빛바램·엉킴 등. 어떤 도구로 몇 번 문질러야 하는지, 보이는 모습(셰이더 값) | 사람이 처음 몇 개를 만들고 AI가 변형 추가 |
| 방 틀 | `content/rooms/<방ID>/room.json` | 벽·바닥·조명, 자리(슬롯) 목록, 기본 소품 배치, 테마 색 | AI가 작성, 사람이 미리보기로 확인 |
| 이야기 조각 | `content/rooms/<방ID>/story.json` | 물건을 고치거나 제자리에 둘 때 열리는 짧은 글(한·영) | AI가 초안, 사람이 문체 다듬기 |
| 의뢰 규칙 | `content/requests/*.json` | "창가만", "깨진 것 3개 먼저" 같은 요청 틀. 생성기가 시드로 채움 | AI가 작성 |

## 3. AI에게 맡기는 순서
1. AI에게 `docs/CONTENT_GUIDE.md`(작성 안내서, 예정)와 예시 방 하나를 읽힙니다.
2. "부엌 테마 방 틀 하나 추가" 같은 한 줄 요청을 합니다.
3. AI가 데이터 파일을 쓰고 `npm run content:check`를 돌려 통과할 때까지 고칩니다.
4. `npm run content:preview <방ID>`로 방 이미지(엉망 상태 / 복원 상태)를 만듭니다.
5. 사람은 이미지를 보고 승인하거나 수정할 점을 말합니다.

## 4. 자동 검사가 막는 것 (`content:check`, 예정)
- 형식: 필수 칸, ID 중복, 숫자 범위
- 참조: 없는 소품·모델·고장 유형을 가리키지 않는가
- 문구: 모든 글에 한국어·영어가 다 있는가, 글자 수 상한
- **풀 수 있는가**: 시드 여러 개로 의뢰를 만들어, 모든 고장이 고칠 수 있고 모든 물건이 갈 자리가 있는지 봇이 끝까지 풀어 봄(쓸어킬의 봇 시뮬레이션 방식)
- 라이선스: 모델 파일이 `docs/ASSETS.md`에 등록된 출처인가

## 5. AI로 쉽게 안 되는 것 (한계)
- **3D 모델 자체**: AI가 화풍이 일관된 3D 모델을 만들기는 아직 어렵습니다. 무료 모델 묶음(CC0)을 **목록화**해 두고, AI는 그 안에서 고르게 합니다. 모델 수가 콘텐츠 상한이 됩니다.
- 그림(액자 속 그림·포스터·라벨 같은 평면 이미지)은 AI 이미지 생성으로 채울 수 있습니다.
- 손맛(문지르는 느낌, 소리, 반짝임)은 코드 쪽 일이라 콘텐츠 추가와 분리합니다.
